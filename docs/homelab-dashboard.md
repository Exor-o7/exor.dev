# Homelab dashboard

The full read-only dashboard is hosted at `https://status.exorverse.com/`, using `status.html` as its source template. The Homelab page keeps the lab introduction and documentation, with a compact linked status overview showing overall health, services available, and last update. Both pages use the same snapshot endpoint and validation/freshness rules in `js/lab-status.js`. The overview loads a small dedicated script rather than the full dashboard code, and never displays dashboard demo data.

The standalone Exorverse dashboard represents the home network, with Inter typography, neutral charcoal surfaces, restrained chart colors, and clear semantic health indicators. Its stylesheet, header, and favicon are independent of the portfolio theme. Its monitor lives in the sibling `../status` project at the user's request. Read that project's README for installation and operating instructions.

## Current state

The supplied `data/homelab-status.json` is a disconnected placeholder, not real lab telemetry. All health starts unknown. The monitoring stack is installed on the Docker host. It checks ten applications and collects live CPU, RAM, and uptime from Proxmox, TrueNAS, UDM Pro, and the Docker VM. Restricted SSH keys collect the three infrastructure hosts; a private agent supplies Docker VM metrics, including network traffic and backing-filesystem data. iDRAC is excluded at the user's request because TrueNAS represents that server's resources. The standalone dashboard and live snapshot are available at `https://status.exorverse.com/`; public DNS, trusted HTTPS, and CORS for `https://exor.dev` were verified on October 24, 2026. The main website changes in this repository still require publication. Backup monitoring awaits successful-job marker paths.

The dashboard includes overall status, node and service counts, response times, backup freshness, CPU/memory and host network charts, per-node metrics, searchable/grouped service checks, observed availability, filesystem capacity, backup markers, and status-change events. Chart and availability ranges are 1h, 24h, and 7d. Current snapshots refresh every 60 seconds while the tab is visible, without manual refresh, pause, or demo controls. Stale-data detection continues independently of successful refreshes.

Displayed timestamps and chart boundaries use America/Chicago in 24-hour format, independent of the visitor's timezone. Timezone labels follow daylight saving (CDT/CST). Infrastructure cards and the resource-host selector follow UDM Pro, Proxmox, TrueNAS, Docker host order.

The layout places four infrastructure cards above the resource-host selector and two resource charts, followed by service health beside supporting metrics. Services become stacked cards on mobile instead of a horizontally scrolling table. Infrastructure and service rows expand for collection context; recent incidents can expand from four to twenty events. Both chart range controls update the same selected range. Documentation links return to the portfolio's Homelab page.

Expired snapshots or failed refreshes mask current metrics and uptime. Existing history stays labeled as recorded data. Last Backup remains in the top summary; there is no separate backup panel. The interface does not invent temperatures, WAN speed, controller client counts, or filesystem integrity metrics that the collector does not supply.

## Data connection

Both pages are configured to fetch `https://status.exorverse.com/homelab-status.json`. For another host, change `data-status-endpoint` on `#lab-dashboard` in `status.html` and on `#lab-status-overview` in `homelab.html` to the monitor's published HTTPS JSON URL. A cross-origin endpoint must allow GET from `https://exor.dev`; no credentials or internal service URLs are placed in frontend code. The website itself remains a static GitHub Pages site. Only the monitor's sanitized `public/homelab-status.json` should be served, never its configuration or code directory.

The sibling monitor writes schema version 1, with `generatedAt`, `staleAfterSeconds`, and arrays for `nodes`, `services`, `backups`, `history`, and `events`. The page marks current status and measurements unknown on a failed fetch, invalid snapshot, future timestamp, or expired snapshot. Recorded history and backup timestamps remain historical. Host metrics are not inferred from TCP/HTTP reachability. Network charts show selected hosts' traffic, not WAN speed. Availability percentages use known recorded five-minute samples, exclude unknown/maintenance observations, and are not a continuous SLA measurement.

The resource-host selector defaults to Docker host and updates both chart titles and current readings. Each infrastructure row has a View resource history action. History samples now include a `nodes` map with CPU percentage, memory percentage, and optional network rates per host. Existing Docker-only history remains associated with that VM; new hosts begin accumulating history at connection. Host and guest measurements are kept separate. Network traffic is currently available for Docker only. RAM readings on ZFS hosts include ARC cache, with the cache amount labeled. The monitor's memory-health heuristic excludes ARC above its configured minimum; this does not diagnose every form of memory pressure.

Filesystem capacity shows only TrueNAS's `zpool` and `vmpool`. The restricted collector reads each pool's root ZFS filesystem `used` and `available` values. Their sum is the reported usable capacity, rather than raw disk space including parity. Usage includes ZFS accounting such as snapshots and reservations. Child datasets, boot pools, Proxmox storage, and the Docker backing filesystem are omitted. Missing pool measurements remain unknown.

The UDM Pro monthly WAN card shows decimal GB/TB downloaded and uploaded on the primary WAN. Calendar months use America/Chicago. It defaults to the current month to date and offers recorded historical months. The card displays its month selector and totals; explanatory footnotes were removed at the user's request. Data-through timestamps and recorded coverage remain available in the snapshot. These are UniFi's recorded gateway totals, not an ISP billing calculation. Current totals combine closed daily, hourly, and five-minute buckets without overlap; completed months use the controller's monthly summaries. Missing data remains unknown. Only aggregate gateway totals enter the public snapshot; no client IDs, destinations, or traffic-flow details are published. The separate `wanUsage` object on the gateway node does not depend on the dashboard's seven-day resource history.

Service response times measure HTTP checks from the monitoring container to each service, including connection establishment and response headers. Local request preparation is excluded, and the verified TLS context is reused. They do not measure a visitor's internet latency or full browser page load. Early samples collected before the October 24, 2026 timing fix included client setup overhead and are not comparable to corrected samples.

No-JavaScript visitors can still follow the status card to the dashboard and return to the lab documentation. The dashboard shows a notice; all lab overview, infrastructure notes, and service descriptions remain in `homelab.html`.

The monitor also packages the dashboard at `https://status.exorverse.com/`. Its `bundle_dashboard.py` script refreshes the public assets from this repository before a Docker rebuild. Operational files and internal addresses are excluded from that bundle.

The previous dashboard host, `status.exor.dev`, is retired, with no configured dashboard route, redirect, or data aliases. The root domain `exorverse.com` is reserved for a future page.
